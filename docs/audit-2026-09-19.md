# Repository audit — 2026-09-19

Repository-wide review of the curriculum scheduler at `d3e1d12` plus the existing uncommitted work. The starting tree already contained extensive application changes and regression tests; this report distinguishes those from fixes added in this pass. Existing changes were preserved. No commit, release, or deployment was performed.

The review covered application code, database initialization and migrations, API ownership and validation, browser behavior, image generation, backup/restore, tests, dependency metadata, CI, release scripts, and user-facing documentation. No new critical/high-severity vulnerability was demonstrated. This is a repository audit, not certification of a deployed server or a claim that every possible input is covered.

### Standalone probe side effect

The standalone visual-export probe initially omitted `DB_PATH`. Before the import-isolation fix, importing `schedule-helpers.js` opened `data/data.db`. A metadata check caught the main database growing from 876,544 to 884,736 bytes and the existing WAL/SHM files disappearing, consistent with SQLite checkpointing the WAL on process exit. The probe passed synthetic arrays to the renderers and issued no data-changing SQL. Logical pre/post database equality was not captured, so a claim that all application data files remained byte-for-byte unchanged would be incorrect.

A copied database was opened read-only and passed `PRAGMA quick_check`; the synthetic export class names and named audit accounts checked were absent. No database rollback or replacement was attempted. The import-isolation fix prevents this dependency side effect and has a regression test that uses only a temporary path.

Application data file sizes and modification times remained unchanged during the post-fix verification runs, including the final complete suites.

## Remaining findings

These are recorded follow-ups, not implicitly fixed by passing tests. Items inherited from the earlier audits were rechecked against current source. Priorities assume the current authenticated, primarily single-instance deployment model.

| Priority | Finding and evidence | Suggested follow-up |
| --- | --- | --- |
| Medium | **API keys remain plaintext in `teachers.api_key`.** Middleware looks up that value directly. Reading the database therefore exposes reusable account credentials. | Introduce a compatible hash-based key lookup/migration and decide how existing keys and the Settings display transition. |
| Medium | **Deployment privilege isolation is weak.** The generated system service has no `User=` and Chromium is launched with `--no-sandbox`/`--disable-setuid-sandbox`. This is source inspection, not a finding about the current host's installed service. | Package a dedicated service identity and document/test ownership, browser cache paths, and a supported Chromium sandbox arrangement. Avoid silently changing an existing host's service account. |
| Medium | **Backup restore still permits legacy scalar/time/enum values that ordinary CRUD rejects.** The current filtering deliberately addresses references and schedule/holiday dates; it is not comprehensive row validation. | Specify a compatibility policy and report unusable values before broadening normalization. Preserve the explicit disk-snapshot undo exemption and editable legacy semester/pricing behavior. |
| Low | **Finite monetary inputs have no practical upper bound.** A finite value can still overflow multiplication/aggregation; restore also bypasses the new monetary guards. | Agree on business limits or explicit overflow handling for derived revenue; do not treat finite-input validation as complete financial validation. |
| Low | **Other scalar validators remain permissive.** For example, single-element arrays can pass some integer/enum chains, and coordinate coercion can accept booleans. | Specify accepted scalar types consistently while retaining intentional numeric-string compatibility. |
| Low | **Pricing has two write/display meanings.** Class PUT accepts price fields although revenue prefers pricing history; the latest future pricing row is labelled “当前定价”. | Clarify the API contract and distinguish latest versus currently effective pricing in the UI before changing persisted behavior. |
| Low | **Collection/settings failure states and asynchronous edits need further work.** Several list screens use a toast with empty or retained data. `SubjectSection` can apply a late profile response over edits; ClassForm applies geocoding coordinates without checking whether the location text changed meanwhile. | Add targeted load/edit guards and recovery tests. These cases were identified from source; delayed-network reproductions were not added in this pass. |
| Low | **Accessibility remains incomplete.** Many visible form labels lack input associations, some clickable calendar/class cards lack keyboard activation, toast announcements and reduced-motion behavior are incomplete. | Audit complete keyboard/screen-reader flows and associate labels, semantics, announcements, and motion preferences. The new focus tests cover only specific repaired paths. |
| Low | **Dense/short export labels remain difficult to read.** Weekly blocks prioritize the time text; monthly short lessons use very small text. The synthetic 30-minute sample confirms the readability limitation. | Choose a presentation policy for dense/short lessons, such as a minimum text area or an accompanying legend, and verify both UI and exports. |
| Low | **Large teacher-scoped summary/export/conflict queries lack the date-span bound used by the ordinary list endpoint.** SQLite operations and rendering can occupy the process under large datasets; this is not demonstrated cross-teacher access. | Define acceptable dataset/range/concurrency budgets and measure realistic loads before imposing incompatible caps. |
| Low | **Multiple processes sharing SQLite remain a distinct operating mode.** First-account checks and backup snapshot capture are not one cross-process claim/snapshot transaction; caches are process-local with TTL. | Document single-instance expectations or add explicit multi-process transaction/concurrency tests before advertising that deployment mode. |
| Low | **Authentication/response consistency follow-ups remain.** Unknown usernames skip bcrypt comparison; some foreign-resource cases return 403 while other routes use 404. CORS compares host rather than the complete origin. | Review these conventions together with reverse-proxy and authentication deployment requirements. No bypass was demonstrated here. |

Operational limits retained: historical bcrypt password-length compatibility, best-effort audit logging, five pre-restore snapshots per teacher, finite cache TTLs, and external geocoding availability. Live TLS/proxy/service configuration, filesystem permissions, upstream AMap availability, long-duration load, and backup disaster recovery on a deployed host were not exercised.
